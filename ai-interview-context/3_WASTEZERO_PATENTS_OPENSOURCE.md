- **Roles (3):** volunteer (default), ngo (secret code at sign-up), admin (secret key). README's "Agent" role doesn't exist. Server middleware (`protect`, `ngoOnly`, `adminOnly`) enforces roles; React `ProtectedRoute` only hides pages. Ownership checks: an NGO's edit query includes its own id, so another NGO's post is "not found".
- **Login:** page trims input → AuthContext `login()` posts `/api/auth/login` (cookies on) → server `findOne` with `+password`, `bcrypt.compare` (cost 10), signs JWT `{id, role}` for **30 min**, sets an **httpOnly** cookie (`secure` + `SameSite=None` in production, `lax` in dev) → client calls `/api/auth/profile` (via `protect`: cookie first, then Bearer header) → stores user in context → effect redirects to `/ngo-dashboard`, `/user-dashboard` or `/admin-dashboard`.
- **Apply:** `POST /api/applications/:id/apply` → protect + role → opportunity must be open → pre-check existing (409) → create pending. **Double-apply stopped in 3 layers:** disabled button, controller pre-check, and a compound **unique index** on (opportunity_id, volunteer_id), the real guarantee even in a race.
- **OTP login:** 6-digit code by email; `Otp` document with `expiresAt` = now + 10 min; verify queries `expiresAt > now` (exact expiry), then deletes it (single use); TTL index lets MongoDB clean up (~every minute).
- **Other:** references + `populate` (an opportunity has many applications; embedding would grow unbounded); `lean()` = plain objects; unique `User.email`; ObjectId checks with `router.param`; `/health`, graceful shutdown, 5 DB retries.
- **Works:** public opportunity list/detail; NGO create/edit/delete with image; volunteer apply and "my applications"; NGO accept/reject via `PATCH /api/applications/:id/status`; admin read views; password register/login/logout.
- **Choices (say "the usual reason is…"):** MERN: one language, JSON end to end (alt Spring Boot). MongoDB: flexible and quick, **but my data is relational, so PostgreSQL would also fit** (joins, reports, transactions). JWT: stateless, scales behind a load balancer; cost: can't revoke before expiry (suspension needs a DB check; Redis sessions revoke easily). httpOnly cookie over localStorage: XSS can't read it; cost: CSRF needs SameSite or a token. bcrypt: salted, slow on purpose; same password gives different hashes.
**Weaknesses (found in my own review; say first, then the fix)**
1. **`req.user.id` vs `req.user._id` (biggest):** `protect` sets only `{id, role}`, but ~38 controller places read `req.user._id`/`.name`. Chat sending, pickups, user-profile endpoints, NGO accept/reject on the routed page and admin activity logging fail (500) or return empty data. Fix: load the user once in `protect` and set `id`, `_id`, `role`, `name`, `isSuspended`. Core opportunity/application flows use `req.user.id` and work.
2. **Suspension not enforced:** admin sets `isSuspended`, but `protect` never reads it and login doesn't check it (stateless JWT can't block a logged-in user without a DB lookup).
3. **Route-order bug:** `GET /:id` is declared before `/pickups`, `/notifications`, `/statistics` in `userRoutes.js`, so Express returns 400 "Invalid user ID"; this also makes the volunteer dashboard fail. Fix: move `/:id` last.
4. Token also kept in localStorage (weakens httpOnly), no refresh token, logout doesn't remove it. 5. **OTP weak:** `Math.random`, plain-text storage, no attempt limit; new-email OTP sign-up fails (`password` required). Fix: `crypto.randomInt`, hash the code, count attempts.
6. Production CORS list is localhost-only (move to an env variable); uploads on local disk (use cloud storage); shared secret codes for ngo/admin; no CSRF protection with `SameSite=None`; CSP allows `unsafe-inline`/`unsafe-eval`; IDOR gaps (any user can mark/delete any notification, read any profile); global error handler ignores `res.statusCode` (some 400s become 500); auth rate limiter also counts `GET /profile`; `.env` was committed once and stays in git history (rotate). 7. README overstates: Socket.io real-time chat (chat is plain REST), Agent role, rewards system and live map (static pages), "production-ready", OWASP compliance.

**Patent 1: toll system** (App. No. 202641056093; with Dr. Priya V, N Sakthivel, C Edward). Filed title *Secure Toll Management System With Cryptographic Authentication And Transaction Sequencing* (disclosure form: "Hybrid Toll Management System (HTMS) with Self-Healing Trust Governance and Tamper-Evident Transaction Sequencing").
- **Problem:** FASTag/RFID toll systems are centralized with weak checks on reader devices: replay attacks, rogue/compromised readers, tamperable records.
- **Reader:** ESP8266/ESP32 + MFRC522 (13.56 MHz) hashes the tag UID (SHA-256), builds an event {hashed UID, reader ID, timestamp, nonce}, signs with HMAC-SHA256 using a per-device key, buffers up to 10 events offline. **Backend (FastAPI)** checks signature, nonce uniqueness (replay), timestamp drift, request rate; then trust, fraud, approval.
- **Trust governance:** each reader has a score 0–100; penalties: auth failure −40, balance manipulation −30, replay −15, abnormal volume −12, rate breach −10; below a threshold (example 35) it is quarantined. **Self-healing in 3 stages:** time-decay `recovery = 2.0 × ln(1 + hours)` capped (example 80); probation challenges (KNOWN_TAG, TIMING_CHECK, HASH_VERIFY); peer consensus (≥2 voters, ≥60% approval, no self-vote). Cross-reader suspicion: tags recently scanned by a quarantined reader get stricter fraud checks for a while.
- **Fraud detection:** rules + supervised tree-based ML + anomaly detection → one fraud score (features: amount, speed, inter-arrival time, sin/cos hour) → approve/flag/reject.
- **Tamper-evident sequencing:** `vdf_input = SHA256(prev_output + event_id + tx_hash + reader_id + timestamp)`, `vdf_output = SHA256^1000(vdf_input)`; changing, inserting, deleting or reordering any record breaks the chain, detected per link. Batches go into a **Merkle tree** and only the **Merkle root** is anchored on a blockchain (tested on local Ganache), keeping on-chain data small.
- **Evidence (simulation/prototype):** 48 automated tests passed (2.95 s); simulated 10,000+ transactions, 5 tags, 3 readers; chain step (1000 hashes) under 50 ms; example trust recovery 60 → 73.8 after 24 h; on simulated data the hybrid ensemble scored accuracy 0.95, precision 0.92, recall 0.89, F1 0.90 vs 0.92/0.88/0.85/0.86 for the supervised model alone; a hardware prototype (ESP8266 + RFID + LCD "Access Granted/Denied") exists.
- **Expected challenge:** a true VDF verifies faster than it computes; ours is 1000 sequential SHA-256 hashes (a sequential hash chain whose check recomputes the work). Say so; it still gives ordered, tamper-evident records.
**Patent 2: federated physics-informed neural network for semiconductor quality control** (App. No. 202641065392; with Dr. E.P. Ephzibah; specification dated 5 May 2026; 10 claims).
- **Problem:** detect anomalies early in semiconductor fabs (India's PLI-scheme fabs), explain them physically, learn across fabs without sharing raw wafer data, automate compliance reporting.
- **Layers:** sensors → **digital twin** (India-Adapted Digital Twin Schema extending IEC 63278 Asset Administration Shell in JSON-LD; monsoon-humidity, grid-quality (voltage sag/swell) and supplier-variance data; synced every 100 ms) → **federated layer** → **compliance layer** (maps anomalies to SEMI E10/E35/E116, auto-generates PLI audit XML).
- **Model:** **LSTM-autoencoder** learns normal behaviour; high reconstruction error = anomaly. Physics terms in the loss: `L_total = L_recon + 0.1·L_Rayleigh + 0.1·L_Electromigration + 0.1·L_Diffusion`; Rayleigh limit `CD = k1·λ/NA = 0.40×193 nm/0.93 = 83 nm`; Black's equation for electromigration (n=2, Ea=0.8 eV, T=378 K, Jmax 2.5×10⁶ A/cm²); Fick's diffusion (erfc profile). **Why:** physics terms stop impossible predictions, reduce data needs, and tag *which law was violated* (explainable). Edge inference on Jetson Orin NX < 100 ms.
- **Federated:** local training per fab; **FedProx** (μ=0.01) keeps local models near the global one; **Gaussian differential privacy** (ε=1.0, δ=10⁻⁵, σ=1.08, per-round ε=0.33); **INT4 quantization** = 8× less bandwidth; Flower coordinator aggregates every 4 h. Output: anomaly score + violation tags → SEMI classification → MTBF, cost-of-ownership, OEE updates → severity decides Grafana alert + PagerDuty or an InfluxDB log.
- **Spec figures (defect-injection validation, worded "may"):** detection 6.6 h vs 17.8 h for periodic inspection (63% faster); physics constraints may cut training-data needs by ≥33%.
