## How it works
- **Stack:** React 19 + Vite 7 + Tailwind 4 + Axios + Context API + React Router 6 · Node + Express 5 · MongoDB + Mongoose 9 (10 models, 9 route files) · JWT, bcryptjs, cookie-parser, Multer (5 MB; jpeg/png/webp), Nodemailer (OTP email), Helmet, CORS with credentials, express-rate-limit. **No tests, no CI, no start script.**
- **Roles (3):** volunteer (default), ngo (needs a secret code at sign-up), admin (needs a secret key). The README's "Agent" role does not exist. Server middleware (`protect`, `ngoOnly`, `adminOnly`) enforces roles; React `ProtectedRoute` only hides pages.
- **Layers:** routes → middleware → controllers → Mongoose models (no service layer). Request pipeline: helmet → compression → cors → JSON (10 MB) → cookieParser → rate limiters (production only: 10/hour on `/api/auth`, 120/min on `/api`) → routes → 404 → global error handler.
- **Login walkthrough:** Login page trims email/password → `login()` in AuthContext posts `/api/auth/login` (cookies on) → server finds user by email with `+password`, `bcrypt.compare` (cost 10), signs a JWT `{id, role}` valid **30 min**, sets it as an **httpOnly** cookie (`secure` + `SameSite=None` in production, `lax` in dev) and returns user data → client calls `/api/auth/profile` (goes through `protect`, which verifies the cookie, then a Bearer header) → stores user in context → an effect redirects to `/ngo-dashboard`, `/user-dashboard` or `/admin-dashboard` by role.
- **Apply flow:** `POST /api/applications/:id/apply` → `protect` + role check → load opportunity, must be open → check for existing application (409) → create with status pending. **Double-apply is stopped in 3 layers:** disabled button in React, controller pre-check (409), and a compound **unique index** on (opportunity_id, volunteer_id), which is the real guarantee even in a race.
- **OTP login:** 6-digit code emailed with Nodemailer; stored in an `Otp` document with `expiresAt` = now + 10 min; verify queries for `expiresAt > now` (exact expiry), then deletes the record (single use); a TTL index lets MongoDB clean up (runs about once a minute).
- **Other facts:** relationships via references + `populate` (an opportunity has many applications, so no embedding); `lean()` returns plain objects; Application has the compound unique index; `User.email` unique; ObjectId validation with `router.param`; ownership checks (an NGO's edit query includes its own id, so another NGO's post is "not found"); `/health`, graceful shutdown, 5 DB-connection retries.
- **What works:** public opportunity list/detail; NGO create/edit/delete with image; volunteer apply and "my applications"; NGO accept/reject via `PATCH /api/applications/:id/status`; admin read views (stats, users, logs); password register/login/logout.

## Why these choices (say "the usual reason is…")
MERN: one language and JSON end to end (alt: Java Spring Boot). MongoDB: flexible documents, quick start, **but my data is quite relational, so PostgreSQL would also fit**, especially for joins, reports and transactions. JWT in cookie: stateless, so several instances work behind a load balancer; cost: can't revoke before expiry (suspension needs a DB check; sessions in Redis revoke easily). httpOnly cookie over localStorage: JavaScript (XSS) can't read it; cost: cookies are sent automatically, so CSRF needs SameSite or a token. bcrypt: salted and slow on purpose; same password gives different hashes. REST over JSON: simple, familiar.

## Weaknesses: say these first, then the fix (found in my own review)
1. **`req.user.id` vs `req.user._id` bug (biggest):** `protect` sets only `{id, role}`, but ~38 places in controllers read `req.user._id` (and `req.user.name`). Result: chat sending, pickups, user-profile endpoints, NGO accept/reject on the routed page and all admin activity logging fail (500) or return empty data. Fix: load the user once in `protect` and set `id`, `_id`, `role`, `name`, `isSuspended` (or replace `_id` with `id`). Core opportunity/application flows use `req.user.id` and work.
2. **Suspension not enforced:** admin sets `isSuspended`, but `protect` never reads it and login doesn't check it. Same fix: DB lookup in `protect` (a stateless JWT alone can't block an already-logged-in user).
3. **Route-order bug:** `GET /:id` declared before `/pickups`, `/notifications`, `/statistics` in `userRoutes.js`, so Express matches `/:id` first and returns 400 "Invalid user ID". Fix: move `/:id` to the end. This also makes the volunteer dashboard show "Failed to load dashboard".
4. **Token also stored in localStorage** (weakens httpOnly), no refresh token, and logout doesn't remove the saved token.
5. **OTP weak:** `Math.random` (not crypto), plain-text storage, no attempt limit; new-email OTP sign-up fails because `password` is required. Fix: `crypto.randomInt`, hash the code, count attempts, make password optional for OTP users.
6. **Production CORS list is localhost-only** (should come from an environment variable); **uploads on local disk** (should be cloud storage); `ngo`/`admin` guarded by shared secret codes (admins should be seeded; NGOs approved by an admin); no CSRF protection while the cookie is `SameSite=None`; CSP allows `unsafe-inline`/`unsafe-eval`; some IDOR gaps (any user can mark/delete any notification, read any user profile); global error handler ignores `res.statusCode`, so some 400s become 500; auth rate limiter also counts `GET /profile`, so real users could be limited; secrets (`.env`) were committed once and remain in git history, so rotate them.
7. **README overstates:** it claims Socket.io real-time chat (chat is plain REST), an "Agent" role, a rewards system and a live map (static placeholder pages), "production-ready" and OWASP compliance. Say: "the README describes plans; I stick to what the code does."

## Q&A (adapt wording; stay true)
**Was this a job or a virtual programme? Your part?** A virtual, project-based programme (Infosys Springboard Internship 6.0, Feb–Apr 2026) in a mentor-led online team. My part = F3, under 30 seconds. Then offer to walk through any flow.
**Explain the project in one minute.** Use the 30-second pitch + one honest line: "some secondary features such as pickups and chat are only partly working, and I know exactly why."
**What does MERN mean and how do the parts talk?** MongoDB, Express, React, Node. React in the browser sends HTTP + JSON to the Express API on Node; middleware (auth) runs, then a controller uses Mongoose to read/write MongoDB and returns JSON.
**What is REST? PUT vs PATCH? Which status codes?** URLs are resources, the method is the action (GET read, POST create, PUT/PATCH update, DELETE remove). PUT replaces the whole resource, PATCH changes some fields; idempotent: PUT and DELETE are, POST isn't. I used 201 create, 400 bad input, 401 not logged in, 403 wrong role/owner, 404 missing, 409 duplicate application. One flaw: some controllers set 400 then throw and my global handler returns 500.
**What is middleware? Show one.** A function between request and controller with `req, res, next`; it ends the request or calls `next()`. `adminOnly` returns 403 unless the role is admin. `router.post('/', protect, ngoOnly, upload.single('image'), createOpportunity)` is a chain: token check, role check, upload parse, controller. Error middleware has four parameters (`err, req, res, next`).
**Authentication vs authorisation?** Who you are vs what you may do: `protect` verifies the JWT; `ngoOnly`/ownership checks authorise.
**What's in a JWT?** Header, payload, signature. Mine carries id and role plus iat/exp, signed with a secret from the environment. Encoded, not encrypted, so no secrets inside. 30-minute expiry.
**Walk me through login.** (Login walkthrough above, 6–8 sentences.)
**JWT vs sessions? httpOnly cookie vs localStorage?** (Why-choices above; add that I keep a localStorage fallback copy, which weakens it and I'd remove.)
**How do you stop applying twice?** (Apply flow, three layers; the index is the real guard; today a race returns 500 instead of 409, I'd catch error code 11000.)
**How does OTP expiry work? Is it secure?** (OTP login above; honest: `Math.random`, plain text, no attempt limit.)
**Password storage?** bcrypt with a random salt per password and a cost factor of 10; `bcrypt.compare` at login; `password` is `select: false`; hashing is one-way, encryption is reversible.
**What is CORS?** A browser rule: a page may read another origin's response only if the server allows it. I use the `cors` package with `credentials: true` and Axios `withCredentials`. Preflight = an OPTIONS request the browser sends first. Honest: the production allow-list in the repo is localhost-only.
**XSS vs CSRF?** XSS = attacker script runs in my page (httpOnly helps, but the localStorage copy and loose CSP weaken it). CSRF = another site makes the browser send my cookie; I have no CSRF token and the production cookie is `SameSite=None`, so I'd use same-site hosting with Lax/Strict or a CSRF token. CORS does not stop CSRF.
**Why MongoDB? References vs embedding?** (Why-choices above.) References + `populate` because an opportunity can have many applications; embedding would grow without limit.
**How would you make chat real-time and scale the app?** Add Socket.io: authenticate the socket with the JWT, join a private room per user id, save the message first then emit to the receiver's room; Redis adapter across instances. Scaling: stateless API behind a load balancer, uploads to cloud storage, pagination and missing indexes (messages, pickups), Redis for rate limits, queue email sending.
**What would you improve in another month?** (1) Fix `protect` (weakness 1+2). (2) Security: drop localStorage token, add refresh token, CORS from environment, hash OTPs. (3) Jest + Supertest tests, CI, a `start` script. (4) Socket.io chat, finish the pickup lifecycle, cloud uploads. First priority: the middleware fix, because one change repairs many features.
**Is it production-ready? Is anything "smart"?** No (weaknesses 1–7). Nothing is smart in the AI sense; I'd call it a volunteering and recycling-drive platform and mention matching/route planning as future work.
**If a user logs out, is the old token still valid?** Technically yes until it expires (30 min); logout only clears the cookie, and my frontend even keeps a saved token. Fix: short access token + revocable refresh token stored in the database.
**How would you test it / deploy it?** Tests: Jest + Supertest with in-memory MongoDB for auth, role guards, ownership, apply incl. duplicate = 409; React Testing Library for login and `ProtectedRoute`; CI on every push. Deploy: `vite build` to Vercel with `VITE_API_URL`, Express on a Node host with environment variables, managed MongoDB (Atlas); cross-domain cookies need `Secure` + `SameSite=None` and an exact CORS origin; or one parent domain with `Lax`.
**What did you learn?** I came from Java and DSA and was new to MERN; I learned the request flow, JWT/cookies/CORS across two origins, and Mongoose, and I learned to review code critically and find real bugs.
