## How it works
- **User flow:** pick location (weather panel) → pick pest (Dead Heart or Tiller) → upload photo → answer 15 yes/no questions (each with a reference photo) → Analyze → label, image score, questionnaire score, fused score, annotated overlay (base64), optional Gemini advice.
- **Backend (`models.py`, one `DiseasePredictor` per pest, models loaded once at start-up):** photo → temp file → YOLOv8 via Ultralytics (conf 0.25, IoU 0.45, size 640). Dead Heart = segmentation (masks), Tiller = detection (boxes) per the README. **Image score = highest detection confidence.** Answers → 15 numbers (yes=1, else 0, fixed order) → TabNet (loaded with joblib) → probability. **Fusion (late fusion): `final = 0.6 × image + 0.4 × tabnet`; `final ≥ 0.5` ⇒ positive.** Weights and threshold are environment variables, in the first commit and never changed, **never tuned**.
- **Stack:** Python 3.10, FastAPI + Uvicorn, Ultralytics 8.3, PyTorch (CPU-only wheels to keep the image small), pytorch-tabnet, joblib, OpenCV + Pillow (overlay), httpx (OpenWeather), optional Google Gemini · React 18 + Vite, 4 languages (English, Hindi, Tamil, Telugu) for the input flow and weather panel · Docker (python 3.10 slim), docker-compose · stateless, no database · model files about 30 MB in the repo.
- **Routes (7):** `GET /health`; four weather routes (`/weather/current`, `/forecast`, `/disease-risk`, `/disease-risk/{type}`); `POST /predict/deadheart` and `POST /predict/tiller` (multipart: image + questions JSON + language).
- **Weather:** OpenWeather current + forecast, cached 30 min, hand-written rules give a pest-risk score (forecast days stand in for past days on the free plan). It is a **separate early-warning panel; it does not change the verdict**, and the location isn't even sent to `/predict`.
- **Gemini advice:** optional; returns 4–8 short bullets in the user's language, no pesticide brands or doses; if no key it returns an empty list and prediction still works. AI-generated, not agronomist-verified.
- **Domain:** Dead Heart = dying central shoot of young cane (commonly linked to early shoot borer: general knowledge, not in the repo); Tiller = side-shoot stunting/abnormal tillering pressure.
- **Hardest bug (real, from history):** Dead Heart segmentation failed at prediction with `'Segment' object has no attribute 'detect'`. Scripts (`test_segmentation.py`, `fix_segmentation_model.py`, `fix_model_properly.py`) separated "model file + library" from "my app code": load the model and predict on a dummy image, read the checkpoint to find the YOLOv8 size, try moving weights into a clean model. The history shows the Dead Heart model file was replaced and Ultralytics upgraded 8.0.206 → 8.3.176 right after, and I added a fallback so the API doesn't crash. How it truly ended = F2. The scripts do **not** prove the cause and don't test preprocessing or output parsing. Lesson: test the model in isolation first; pin versions.

## Why these choices (say "the usual reason is…")
Late fusion: each model can be built, replaced and debugged separately; no paired photo+answers dataset needed (cost: scores aren't on the same scale and weights are fixed; learn them with logistic regression on a validation set, pick the threshold from a precision-recall curve). YOLOv8: fast on CPU, one library for detection and segmentation (alt: Mask R-CNN, plain classifier). TabNet: the model the team trained; tree models (XGBoost/random forest) are a strong simpler baseline for 15 binary features, **not benchmarked, so never say TabNet is better**. Segmentation shows the exact affected shape; boxes are cheaper to label. FastAPI: typed params, file upload, auto `/docs` (alt: Flask). CPU-only PyTorch: free hosts have no GPU and the image stays smaller. Stateless: nothing to store (alt: save cases for audit/retraining).

## Weaknesses: say these first, then the fix
1. **No accuracy/precision/recall/F1 anywhere.** I won't quote a number. Fix: labelled test set of photos + answers, run the whole pipeline, report precision/recall/F1 per pest, and compare fusion vs image-only vs questionnaire-only. Recall matters most (a missed pest costs more than a false alarm).
2. **The 0.4 ceiling (design flaw):** if YOLO finds nothing (or fails), image score is 0, so the best fused score is 0.4 < 0.5 and the answer is always "NO PEST DETECTED", even if all 15 answers are yes. Reverse: a false detection at 0.25 plus all-yes gives 0.55 = positive. Fix: treat "no image evidence" separately: re-weight to the questionnaire or return "inconclusive" and ask for a better photo; add a plant/not-plant gate.
3. Placeholder probabilities flow silently: TabNet missing → 0.65, any error → 0.5, with no flag. Should be an explicit error.
4. **A real-looking OpenWeather API key was committed** (`.env.example`, a test script) and is in git history. Fix: rotate it, placeholders only, environment variables, secret scanning (gitleaks). Say "I'd rotate it" unless it's done.
5. A bad upload returns 500 instead of 400 (generic `except Exception` catches the 400). No auth, rate limit or upload-size limit (the UI says 10 MB but nothing enforces it). Inference is blocking inside `async` routes, so one request can hold up others; not load-tested.
6. 15-answer order is repeated in three places with nothing enforcing it; unit tests: 5 pass, **1 fails** (stale test), no API tests, no CI; weather thresholds have no cited source and some advice mentions fungicide for insect pests (needs an agronomist); result page and landing page are English-only; location required but unused; confidence "81%" is a weighted score, not a calibrated probability.

## Q&A (adapt wording; stay true)
**Walk me through a prediction.** React sends photo + answers + language to `/predict/<pest>`. Backend saves the photo to a temp file, runs YOLO, takes the highest confidence as image score and draws masks/boxes into a base64 overlay. Answers become 15 ones/zeros in fixed order, TabNet returns a probability. Fused = 0.6 image + 0.4 TabNet, 0.5 or more is positive. Optional Gemini advice, then the UI shows label, both scores, overlay.
**What is YOLO?** "You Only Look Once": one pass over the image gives all detections, so it's fast. I load a `.pt` file with Ultralytics and call `predict`; I get masks or boxes with confidences. IoU = overlap area ÷ union area; NMS keeps the highest-confidence box and drops overlapping duplicates; the library does both, I pass `iou=0.45`, `conf=0.25`.
**What is TabNet?** A deep model for table data that uses attention to pick features at each step; here the "table" is one row of 15 yes/no answers.
**Why combine image and questionnaire? Why 0.6/0.4?** Different signals cover each other's weaknesses (blurry photo vs what the farmer notices). The weights are hand-set defaults, never tuned; I'd fit them on validation data. I haven't proven fusion beats either model alone.
**What accuracy did you get?** I don't have a held-out number and won't make one up; here's how I'd measure it (weakness 1). Any training-time metrics: only if F2 gives them.
**What if the photo is bad or nothing is detected?** (weakness 2, in my own words, with the fix.)
**A dog photo and all-yes answers?** Not tested; by the code: no detection gives at most 0.4 = negative; a false detection at 0.25 gives 0.55 = positive. It can be fooled both ways; I'd add an out-of-distribution gate and an "inconclusive" result.
**Why TabNet, not XGBoost?** TabNet was the team's model; I didn't benchmark; tree models are a strong baseline for 15 binary features; I'd compare with cross-validation.
**Deployment / cold start?** Containerized with Docker (CPU PyTorch); repo targets Railway/Render; live host per F8. A cold start is the delay on the first request after the app was asleep: container boot + importing PyTorch/Ultralytics + loading four model files; mitigate with a keep-alive ping to `/health` or one minimum instance. State a measured number only if F8 has one.
**What was your part in the team?** Use F2 only, in under 30 seconds.
**Hardest bug?** The segmentation bug story above, ending per F2.
**CORS?** Browsers block a page from reading another site's response unless the server allows it; FastAPI `CORSMiddleware` has a list of allowed origins (localhost, a Render URL, plus extras from an environment variable). It protects browsers only, not direct callers, so it isn't authentication.
**How does multilingual work?** A small React Context `t()` helper with one JSON file per language (146 keys each), choice saved in localStorage and sent to the backend so Gemini answers in that language. Honest gap: result and landing pages are English-only.
**Security problems?** Committed key (rotate), no auth/rate limit/size limit, `.pt`/`.joblib` files can run code when loaded so only trust our own, unescaped Gemini text in the downloadable HTML report.
**How would you improve it?** (1) Measure (labelled set, precision/recall/F1). (2) Fix fusion (inconclusive/re-weight; learn weights and threshold). (3) Remove placeholder probabilities; correct status codes. (4) Pydantic schemas, API tests, CI; move inference off the event loop. (5) Compare TabNet with XGBoost; agronomist review of weather rules. (6) Store confirmed cases, with consent, to retrain.
**Does the farmer's decision depend on this?** It's a decision aid, not a diagnosis; it should say "inconclusive" when unsure, carry a disclaimer, and point to the local extension office.
